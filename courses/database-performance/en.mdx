Most slow applications are slow in the database, and most slow databases have one of a few causes. The good news: they are easy to find once you know where to look, and the fixes are usually small.

This course follows the order you would use at work. First you **measure** to find the query that matters. Then you learn what an **index** does and how to read a query plan. Then you fix the most common ORM mistake, **N+1 queries**, and finish with **pagination** that stays fast on page 1,000.

The examples use PostgreSQL. Every idea works the same in MySQL; only some commands and tool names differ.
