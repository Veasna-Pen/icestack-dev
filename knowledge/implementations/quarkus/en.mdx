Production patterns for Quarkus 3+ on Java 21+. Covers declarative resilience annotations with SmallRye Fault Tolerance, Agroal database pool tuning, reactive Mutiny Redis caching, and transactional idempotency.

## Timeouts first (SmallRye Fault Tolerance)

Quarkus leverages MicroProfile and SmallRye Fault Tolerance annotations to enforce non-blocking execution deadlines:

```java
package com.example.rates;

import jakarta.enterprise.context.ApplicationScoped;
import jakarta.ws.rs.client.ClientBuilder;
import jakarta.ws.rs.core.Response;
import org.eclipse.microprofile.faulttolerance.Timeout;
import org.eclipse.microprofile.faulttolerance.Fallback;
import java.time.temporal.ChronoUnit;

@ApplicationScoped
public class ExchangeRateService {

    @Timeout(value = 2, unit = ChronoUnit.SECONDS)
    @Fallback(fallbackMethod = "fallbackRates")
    public String getLatestRates() {
        Response response = ClientBuilder.newClient()
                .target("https://api.example.com/rates")
                .request()
                .get();

        if (response.getStatus() != 200) {
            throw new RuntimeException("Upstream failed with status " + response.getStatus());
        }
        return response.readEntity(String.class);
    }

    public String fallbackRates() {
        return "{\"status\":\"cached_fallback\",\"rate\":1.0}";
    }
}
```

## Retry and Circuit Breaker

Combine `@Retry` with `@CircuitBreaker` to handle transient network blips without causing cascading outages:

```java
package com.example.inventory;

import jakarta.enterprise.context.ApplicationScoped;
import org.eclipse.microprofile.faulttolerance.CircuitBreaker;
import org.eclipse.microprofile.faulttolerance.Retry;
import java.time.temporal.ChronoUnit;

@ApplicationScoped
public class InventoryClient {

    @Retry(
        maxRetries = 3,
        delay = 200,
        delayUnit = ChronoUnit.MILLIS,
        jitter = 100,
        retryOn = { java.io.IOException.class, jakarta.ws.rs.WebApplicationException.class }
    )
    @CircuitBreaker(
        requestVolumeThreshold = 10,
        failureRatio = 0.5,
        delay = 5,
        delayUnit = ChronoUnit.SECONDS
    )
    public ItemInventory checkStock(String sku) {
        // Call downstream inventory service
        return callDownstreamService(sku);
    }

    private ItemInventory callDownstreamService(String sku) {
        // Implementation
        return new ItemInventory(sku, 42);
    }
}
```

## Database connection pool (Agroal)

Quarkus uses Agroal for high-performance, lightweight database connection pooling. Configure pool limits and statement timeouts in `application.properties`:

```properties
# application.properties
quarkus.datasource.db-kind=postgresql
quarkus.datasource.jdbc.url=jdbc:postgresql://localhost:5432/orders_db
quarkus.datasource.username=postgres
quarkus.datasource.password=secret

# Agroal Pool Configuration
quarkus.datasource.jdbc.min-size=5
quarkus.datasource.jdbc.max-size=30
quarkus.datasource.jdbc.acquisition-timeout=3S
quarkus.datasource.jdbc.idle-removal-interval=5M

# PostgreSQL Statement Timeouts
quarkus.datasource.jdbc.statement-timeout=5S
```

## Idempotency with Panache and `@Transactional`

Enforce at-most-once processing using database unique constraints and Jakarta transactions:

```java
package com.example.orders;

import jakarta.enterprise.context.ApplicationScoped;
import jakarta.transaction.Transactional;
import jakarta.ws.rs.*;
import jakarta.ws.rs.core.Response;

@Path("/orders")
@ApplicationScoped
public class OrderResource {

    @POST
    @Transactional
    public Response createOrder(
            @HeaderParam("Idempotency-Key") String key,
            OrderRequest request) {

        if (key == null || key.isBlank()) {
            return Response.status(Response.Status.BAD_REQUEST)
                    .entity("Idempotency-Key header is required")
                    .build();
        }

        IdempotencyRecord record = IdempotencyRecord.findById(key);
        if (record != null) {
            if (record.responseBody != null) {
                return Response.status(record.statusCode).entity(record.responseBody).build();
            }
            return Response.status(Response.Status.CONFLICT)
                    .entity("Request is currently in progress")
                    .build();
        }

        // Claim key
        IdempotencyRecord claim = new IdempotencyRecord(key);
        claim.persist();

        // Create domain order
        Order order = new Order(request.customerId, request.totalCents);
        order.persist();

        claim.statusCode = 201;
        claim.responseBody = "{\"orderId\":\"" + order.id + "\"}";
        claim.persist();

        return Response.status(Response.Status.CREATED).entity(claim.responseBody).build();
    }
}
```

## Reactive Caching with Mutiny and Redis

Use the reactive Redis client for low-overhead caching:

```java
package com.example.cache;

import io.quarkus.redis.datasource.ReactiveRedisDataSource;
import io.quarkus.redis.datasource.value.ReactiveValueCommands;
import io.smallrye.mutiny.Uni;
import jakarta.enterprise.context.ApplicationScoped;
import java.time.Duration;

@ApplicationScoped
public class ReactiveProductCache {

    private final ReactiveValueCommands<String, String> countCommands;

    public ReactiveProductCache(ReactiveRedisDataSource ds) {
        this.countCommands = ds.value(String.class);
    }

    public Uni<String> getProduct(String id) {
        String key = "product:" + id;
        return countCommands.get(key)
                .onItem().ifNull().switchTo(() -> fetchFromDbAndCache(key, id));
    }

    private Uni<String> fetchFromDbAndCache(String key, String id) {
        // Query database reactively
        String data = "{\"id\":\"" + id + "\",\"name\":\"Widget\"}";
        return countCommands.setex(key, Duration.ofMinutes(5).toSeconds(), data)
                .replaceWith(data);
    }
}
```
